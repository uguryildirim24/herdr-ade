# D7 — dispatch sends an unbounded payload, and hides what the server said

Work in `/home/agent/projects/herdr-ade`. Two related defects in `src/jev.rs`
and the dispatch state builders, found live at 2026-09-20 03:50Z.

## What happened

`ha round advance` could not start the reviewer for round `r44`. It said:

```
round r44: the reviewer did not start (jev_transport: request failed (exit Some(56), timeout false))
```

`r44`'s member lane committed a 582 KB JSON file and a 150 KB report. The review
dispatch state carries the pinned lane's diff, so the request body was about
750 KB. TypeSafe answers a body that size with **HTTP 400**. Reproduced exactly:
the same config file through `/usr/bin/curl --disable --silent --show-error
--fail --max-time 30 --config -` exits 56 with `curl: (56) The requested URL
returned error: 400`, while a small body to the same endpoint with the same key
returns 200 in 0.34 s.

So there are two defects, and the second is why the first took a while to find.

## D7a — bound what dispatch sends

Nothing limits the size of the state. `dispatch_repository` sends the whole of
`git ls-files` and `git log -5 --oneline --stat`; the review path adds the
committed review brief and the pinned lane diffs. Any of them can be arbitrarily
large, and a lane that commits a large generated file makes its own review
undispatchable.

Give the state a budget. Decide the shape yourself and say why in your report,
but it must hold:

- the request never exceeds a byte cap that you pick and justify against what
  the endpoint actually accepts (measure it; do not guess from documentation);
- when something is cut, the state says so in a field the model can see, so a
  judgement is never made on a silently truncated brief while believing it is
  whole;
- the **task brief itself is never silently dropped**. If the brief alone
  exceeds the cap, that is a refusal with a reason, not a quiet trim.
- what gets cut first is the cheapest evidence, not the task. A file list and a
  diff are summaries; the brief is the question.

Record the cut in the dispatch ledger entry so a later evaluation knows the
judgement was made on less than the whole.

## D7b — say what the server said

`jev_transport: request failed (exit Some(56), timeout false)` names curl's exit
code and nothing else. The server's status and its message are both available
and both were thrown away, so a 400 that names the cause reads as a transport
fault.

Capture the HTTP status and the response body on failure and put them in the
error. Keep the key off argv and out of the child environment, as now, and make
sure nothing in the new error text can carry it. Distinguish, in the message: a
refusal by the server with its status and text; a timeout; and a real transport
failure.
