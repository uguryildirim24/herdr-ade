## 1. `round admit` refuses a sha that is already on the integration branch

Reported by the flyonenomics coordinator, confirmed in the code: `round admit`
(`src/round.rs`, the admit path around line 669) only calls `refresh_pins` and
never compares the lane's pinned sha against the round's integration branch. It
admitted two lanes whose last done sha was already merged into `main`. The

review was spent on a candidate that contained nothing. The reviewer correctly
returned REJECT.

Make `admit` refuse when the sha it would pin is already an ancestor of the
round's integration branch (`git merge-base --is-ancestor`), with an error that
says so in plain words and names the sha and the branch. A lane whose newer done
event has not arrived yet must be distinguishable from a lane with nothing new:
say which case it is.

`round advance` must not start a reviewer for a round whose every member pins an
already-merged sha.
