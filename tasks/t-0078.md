## What to build

**The coordinator never names a model.** `thread start` takes no `--role` and no
`--recipe`. It takes the task and the repository. At dispatch the harness sends
the task text and the relevant state to Jev, Jev returns the model, the harness
starts the lane on it. A coordinator that tries to name a model is refused.

**Jev is TypeSafe's System One model.** The key is in the environment as
`TYPESAFE_API_KEY`. Read the live docs before writing the call —
`https://docs.typesafe.ai/llms.txt` for the index, then the API page and the
`Choice` primitive. Ask a `Choice` over the available models, with the task text
and the state as the question's state. Ask any further judgments you find useful
(difficulty, whether it touches a build or install path, how much code it must
read) as separate questions in the same request, since independent questions run
in parallel. Use the returned probabilities: a low-confidence pick is worth
recording in the ledger, not worth blocking on.

**Four exclusions, decided by rule and never sent to Jev:**

1. **Web research is `agy`.** It replaces web search; when the work is research
   on the open web, that is the answer without asking.
2. **The claude binary** where the work must be Claude, including a coordinator.
3. **Writing a spec goes to Fable, or to Pro through the relay.** Not Jev's
   choice.
4. Anything Rolf pins by hand, if he ever does.

**Failure escalates itself.** A lane that fails asks again with the failure as
part of the state, and gets a stronger model. No settings edit, no permission
step, no `escalate` list a coordinator may not touch. Bound the escalation so it
cannot climb forever, and record each escalation in the ledger.

**Review keeps its place in the flow.** `round advance` still starts a review.
Its model comes from the same picker, reading what is actually being reviewed —
not from `[roles.reviewer]`.

**The roles table goes.** `[roles.*]` in `~/.config/herdr-ade/config.toml` is
deleted along with the code that reads it. `[recipes.*]` stays: it is the list of
models the picker chooses from, and each row needs whatever description Jev needs
to choose well. `doctor` refuses a config that still has `[roles.*]`, naming what
to remove. Update `skill/COORDINATOR.md`: the section on model choice becomes
"you do not choose; describe the work well, because that description is what
picks the model", and `docs/operations.md` to match.

Do not edit `~/.config/herdr-ade/config.toml` yourself. Say in your report
exactly what has to change there and the coordinator does it at install.
