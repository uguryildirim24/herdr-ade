## The protocol

- The relay's instructions to the model (the Pro home's `model_instructions_file`, or a relay-owned preamble added to the first message of each session, whichever the relay already controls; read `src/pro/home.rs` and `src/pro/serve.rs` to see which) describe two request lines the model may put at the END of an answer, one per line, nothing after them:
  - `READ <absolute path>` — the relay answers with the file's text.
  - `LIST <absolute directory>` — the relay answers with the directory's entries (name, kind, size), no recursion.
  A reply that ends in request lines is not final: the relay does not return it to pi. It executes the requests, sends one follow-up message on the same Codex thread (`codex exec resume`, the session mechanism the relay already has) carrying each result under a header `=== <path> ===` (text files as-is, errors as one line), and waits for the next answer. Up to 8 request rounds per pi request; on the 9th the relay returns the last answer with a trailing note that the budget is spent. The 2 h breaker and the in-flight limits stay as they are.
- Allowed roots: `/Users/rolfie/projects` and the worktrees under it, plus any `--read-root <dir>` given to `serve` (repeatable, recorded in `serve.json`). Everything else is refused with one line (`refused: outside the readable folders`), including symlinks that resolve outside, `.git/objects`, and any path containing `auth.json`, `.env`, `id_`, `.pem`, `token`. Reads are read-only; there is no WRITE.
- Caps: 200 KB per file (truncated with a note), 1 MB per round, binary files refused. A LIST of more than 500 entries is cut with a note.
- The bridge prefixes every answer with a "Local tools unavailable" blockquote; the relay strips that blockquote (lines starting with `> ` at the top of the answer, up to the first blank line) before it looks for request lines and before it returns text to pi.
- The relay writes a log: today `serve-run` has stdout and stderr on `/dev/null`, so a refused or failed request leaves no trace. Log every request (session key, bytes in, rounds, files, outcome, codex exit) and every refusal to `<pro-bridge>/relay/serve.log`, appended, one line each; `herdr-pro doctor`'s relay row prints the last line.
- Each pi request's response carries, in the relay's own log line and in `usage.jsonl`, the number of rounds and files read. `herdr-pro doctor`'s relay row shows the readable roots.
