## Traps worth remembering

- Read `ha round merge`'s exit code directly, never behind a pipe. A piped `&&` chain once reported success while nothing had merged, and two threads were resolved on that lie.
- `round advance` used to fail silently to start a reviewer six times in one night; r36 fixed it and the round record now carries `reviewer_start_failures`. Check that field rather than reaching for `ha thread restart`.
- `ha harness install` runs the binary that is already installed, so a fix to the installer itself only takes effect on the *second* run after its merge. The box fork build failed twice for this reason before it worked.
- A box lane whose agent lost its name on the box server is reported as "pane closed / Waiting on you" while it is in fact working; its DONE still arrives through the sealed event.
- `ha thread prompt` refuses a lane in an error or `prompt_pending` state; `herdr pane run <pane> "<short command>"` types into it instead. zsh does not word-split `$var`, so loops over pane ids silently send the wrong pane.
- Box scripts are meant for `ssh remote-host 'bash -s' < script.sh`. Running one on the Mac rebuilds the Mac and leaves stray folders.
- A reviewer that runs `ha done` on its priming task seals an early, wrong sha; the later done of the same attempt supersedes it.
