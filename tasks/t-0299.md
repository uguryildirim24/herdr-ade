## Target

1. **Gates per repo, typed.** Each `[[repos]]` row may carry `gates` (commands) and the environment they
   need. Absent means "not configured" and is reported as such at open; `gates = []` means an explicit
   gate-free repo. Delete the project-wide raw `gates` key. Pin the repo's gate policy at round open, put
   the gates in the review brief, and make the verdict declare, per pinned gate, the command and its exit;
   `advance` rejects a verdict whose declared coverage does not match the pinned set. Coverage alone is not
   proof a command ran; keep the reviewer's actual output in its report.
2. **Open in one command.** `ha round open <slug> [<round>] [<thread>...] [--repo <path>] [--branch <b>]
   --plain "<sentence>"`: the round id defaults to the next free one; given lanes, it infers their one repo
   (refuse mixed repos) and admits them in the same command; without lanes and with more than one repo, it
   refuses without `--repo`, before any side effect. The branch defaults to the repo's integration branch
   (`main` for herdr-ade; read what the repo row or checkout says, do not hardcode). `round admit` stays for
   later lanes.
3. **Merge finishes the job.** After a successful merge, `round merge` pushes the integration ref to the
   repo's allowed remote (add a per-repo push remote setting: the herdr fork pushes to `fork`, never
   `origin`; herdr-ade pushes to `origin`), then runs the installer for repos whose `task_states` include
   `installed`, reusing the existing install code and its proof. A push or install failure leaves the round
   "merged; publish or install pending" (never "merge failed", never verified); running `round merge` again
   resumes only the outstanding step without merging twice. W38 already resolves lanes on merge; reuse it.
