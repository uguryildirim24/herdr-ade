# W11: the install check compares builds by commit (job-0008)

Every `ha harness install` tonight printed, for the box:

    oci herdr-ade binary: herdr-ade 0.1.0+2d22e69.1790044097 (stale)
    oci ticker: unknown (ticker did not report the installed build)

`src/harness.rs` `box_process_proofs` (~736-800) waits for the box `.ticker.lock` to report the Mac's exact
`crate::VERSION` and marks the binary current only if its version contains the Mac's `crate::VERSION`. The
version carries a per-machine build stamp after the commit, so the box can never match. Result: every job stops
at `running processes: unknown; verification is blocked` (job-0010, job-0014 tonight), and `task evidence

## Change

1. Compare builds by the commit part of the version (`0.1.0+<sha>`), ignoring the build stamp, for the box
   binary, the box ticker and anywhere else a local and a remote version are compared (talk screens, doctor
   ticker row). One helper, used everywhere.
2. The box ticker check waits for the ticker lock to report a version with the same commit, and reports the
   pid and exact build it saw.
3. When the running-processes check passes, the tasks carried by that build can take `task evidence --kind
   verified`.

Tests: same commit with different stamps counts as current; a different commit is stale; the box ticker
proof passes on a same-commit lock.
