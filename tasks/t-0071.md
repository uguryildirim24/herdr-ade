# The cloud box builds the terminal program too

In `/home/agent/projects/herdr-ade`, `ha harness install` builds every
repository in `[harness] repos` and installs it here and on the saved box
(`src/harness.rs`). The plugin half works on both machines. The fork half fails
on the box.

`zig_path()` in `src/harness.rs` returns `<repo>/.target/rebase/zig-0.16.0/zig`
and `box_build()` exports that same Mac-shaped path as `ZIG` on the box. The box
has no such directory. The build panics in the fork's `build.rs`:

```
zig executable not found (looked for
"/home/ubuntu/projects/herdr/.target/rebase/zig-0.16.0/zig"; set the ZIG
environment variable to point at the zig binary)
```

The box does have Zig 0.16.0 — at `/home/ubuntu/.local/bin/zig`, installed
during the box setup. Only the path is wrong.

Resolve the box's zig on the box: prefer the repository-local
`<box_repo>/.target/rebase/zig-0.16.0/zig` when it exists, otherwise a `zig` on
the box's PATH, and fail with a clear message naming both places when neither is
there. Verify the version is 0.16.0 before building, and say so plainly if it is
not. The Mac side keeps its current behaviour.

Because of this, the fork row in `~/.config/herdr-ade/config.toml` currently has
no `box_path` and carries a comment saying why. When your change works, put the
row back to:

```toml
{ path = "/home/agent/projects/herdr", box_path = "/home/ubuntu/projects/herdr" },
```

and remove the comment. Prove it by running `ha harness install` yourself and
showing that the box's `~/.local/bin/herdr` is rebuilt from the current
`agent-parent-nesting` head. The box's binary is presently from before round r27,
which is why a box lane does not nest under its coordinator in Rolf's window.

Note for your own build: the box's herdr server is running from that same
binary. Install by staging a temporary file and renaming over it, exactly as the
existing code does. Never stop the box's herdr server.
