## Change

1. `ha task drop <slug> <job> --acceptance <N> --reason "<why>"` withdraws condition N
   only. `--acceptance` may repeat. The reason is required and is stored with the date,
   like whole-task drop evidence. Refuse when the condition already has verified
   evidence, when it is already withdrawn, when N is out of range, or when this would
   withdraw every condition (then drop the task instead).
2. Derivation skips withdrawn conditions. "verify N acceptance condition(s)" counts only
   live, unverified ones, and a task whose remaining conditions are all verified derives
   `verified`. `task show` prints a withdrawn condition as withdrawn, with its reason and
   date, and `TASKS.md` and the talk overview agree.
3. Whole-task `task drop` without `--acceptance` behaves exactly as today. Existing task
   files load unchanged.
4. Tests: withdraw one of three conditions (two verified) → `verified`; each refusal;
   whole-task drop unchanged.
5. In `skill/COORDINATOR.md`, extend the existing `task drop` line in a few words: when a
   newer choice replaces one condition, withdraw it with `--acceptance N` and the reason
   naming that choice. Add the same to `docs/operations.md`.
