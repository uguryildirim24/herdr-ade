# A finished lane leaves nothing behind on the box

Two leaks, one cause: lane workspaces on a remote machine are created with an
unused shell tab and are never removed. Rolf raised this twice — once about the
sidebar on 2026-09-19, once about empty panes overnight on 2026-09-20 — and
neither time was it fixed in the harness.

## What is happening

Every lane started on a remote machine gets its own workspace there. A new
workspace comes with a default shell tab labelled `1`, holding a bash prompt in
the repo directory. The lane's agent tab is then added beside it. The `1` tab is
never used by anything.

Because a lane's tabs are merged into its coordinator's tab row, every lane
shows up twice in Rolf's tab bar: once as itself, once as an empty prompt.

When the lane resolves, `thread resolve` closes the agent's pane and tab — that
part works. It does not close the workspace. The workspace survives with its `1`
tab forever.

Measured on `oci` earlier today: 32 workspaces, 4 with a live agent, 28 empty.
One corpse per finished lane since the project began. I closed them by hand;
three more had accumulated within the hour, so a sweep is not a fix.

## What to build

1. **Do not create the unused tab.** A lane workspace should come up with the
   lane's tab and nothing else. If the remote server's workspace-create always
   makes a first tab, use it for the lane rather than adding a second.
2. **Remove the workspace when its lane ends.** Whatever closes the agent's pane
   and tab on resolve must also close the workspace, on the machine the lane ran
   on, once it holds nothing else. A workspace that still has another tab or a
   live agent is not closed.
3. **Report the leak rather than hiding it.** `ha doctor` counts workspaces per
   machine that hold no agent and belong to no open lane, and fails when there
   are any. A leak that nothing reports is how this survived two complaints.

Apply the same rule on the Mac, not only the box: the cause is shared and the
Mac is only clean today because its lanes run as tabs in the project workspace.
