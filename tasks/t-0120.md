## What to find

- Functions, methods, types, traits, constants, statics and modules nothing
  reaches. Include things reachable only from code that is itself dead: chase
  the closure until it stops shrinking.
- Every `#[allow(dead_code)]`. Each one is either a lie or a deletion. If it is
  genuinely needed, say which caller needs it in your report; otherwise remove
  the code, not the attribute.
- Struct fields that are written and never read, and enum variants never
  constructed.
- Unused dependencies in `Cargo.toml`, and features nothing enables.
- Leftovers from removed features. This project has deleted whole subsystems
  before — the lane picker was removed and reinstated, roles were added and
  then emptied out of the config — so expect orphaned helpers, half-referenced
  constants and error variants for conditions that can no longer occur.
- `pub` that nothing outside the module uses. Narrow it; a needlessly public
  item hides deadness from the compiler.

## Rules that apply

From Rolf's RULES.md, which you already have: remove, do not guard. A dropped
thing is deleted — module, tests, docs, flags. No shims, no fallbacks, no

Do not introduce `#[allow(dead_code)]` anywhere. Do not comment code out.

anything you suspected but left, and why — a thing you could not prove dead is
a finding, not a failure.

Group your commits by area so a reviewer can read them. One commit that deletes
