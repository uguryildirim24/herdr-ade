# The overview keeps one line per row

Rolf's complaint, in his words: the project screen is "prettier" but he "just
see[s] more texts", and it should not be "walls of text". The mockups in the
fork at `tasks/ade/talk-mockups/screen-wide.png` and `screen-narrow.png` are the
target look and they are already what the screen implements. The design is not
the problem. The problem is that a long sentence turns one row into a wrapped
paragraph, and nothing stops that.

Two halves, both in `/Users/rolfie/projects/herdr-ade`.

## 1. A row is one line

In `src/talk/overview.rs` and `src/talk/screen.rs`, every row of the overview
(the part above the chat: the goal, the end result, each step, each running
item, each finished item, each waiting question, each recorded choice) renders
as exactly one terminal line at the current width. Text that does not fit is cut
and ends with a single-character ellipsis. Never wrap an overview row onto a
second line.

The full text must still be reachable: the full overview (F2) shows each row
complete, wrapping there as it does today. Only the compact overview above the
chat is capped.

Respect the existing narrow layout: the cap is the row's available width after
its prefix and any right-hand marker, not a fixed number.

## 2. Long sentences cannot be written in the first place

The plain checker already refuses a `decide` line over 25 words
("write one sentence of at most 25 words"). Apply the same cap to the sentences
that feed the overview's rows:

- a round's `--plain` sentence (`round open`)
- a thread's `--plain` birth sentence (`thread start`, `thread adopt`)
- a plan step's text and the plan's `--does` sentence

Use the checker's existing machinery and its existing error shape; do not invent
a second checking path. Existing records that are already too long must keep
loading and rendering (cut, per part 1) — only new writes are refused.

## Gates

`cargo fmt --check`, the full test suite, and clippy with warnings denied, all
with `PATH=/bin:$PATH DEVELOPER_DIR=/Library/Developer/CommandLineTools`.
Add tests for: a row longer than the width is cut to one line and ends with the
ellipsis; the same row is complete in the full overview; a 26-word round
sentence is refused; a 25-word one is accepted.

Do not add compatibility shims, fallbacks or flags. Do not push. When the work
is committed, run `ha done`.
